# SMTP-релей очереди рекламаций (EmailOutbox)

На проде исходящие SMTP-порты закрыты хостером, а ответы клиентам должны
уходить **с адреса Яндекс-ящика**. Поэтому приложение только кладёт письма в
очередь (`EmailOutbox`), а фактически отправляет их этот скрипт — с машины, где
порт 465 открыт (твой компьютер / отдельный ПК).

## Как это работает

```
DZ_fastapi (прод)                     relay.py (твой ПК)
  очередь EmailOutbox   <── HTTPS ──   1. POST /auth/login
                                       2. GET  /email-outbox/pending
   smtp.yandex.ru:465   <── SMTP ───   3. отправка письма
                        ── HTTPS ──>   4. POST /email-outbox/{id}/mark-sent | /mark-error
```

## Установка

```bash
cd scripts/email_relay
python -m venv .venv && source .venv/bin/activate   # по желанию
pip install -r requirements.txt
cp config.example.json config.json
# отредактируй config.json (см. ниже)
```

## Настройка `config.json`

| Поле | Что это |
|------|---------|
| `api_base_url` | Базовый URL API. Через nginx это обычно `https://dragonzap.online/api`. |
| `auth_email` / `auth_password` | Учётка пользователя приложения, от имени которого релей ходит в API. Заведи отдельного пользователя (например `relay-bot@…`), одобри его в админке. |
| `poll_interval_seconds` | Как часто опрашивать очередь (по умолчанию 30 с). |
| `batch_limit` | Сколько писем забирать за раз. |
| `verify_tls` | Проверять TLS-сертификат API (оставь `true`). |
| `smtp_accounts` | Карта `from-адрес → SMTP/IMAP-настройки`. Ключ — это адрес, с которого письмо должно уйти (адрес ящика рекламаций). |
| `default_smtp` | Запасные SMTP-настройки, если `from` письма не совпал ни с одним ключом. `null` — не отправлять такие. |

После успешной SMTP-отправки релей по умолчанию добавляет копию письма в
IMAP-папку `Sent`, чтобы ответ был виден в Яндекс.Почте. За это отвечают
`save_to_sent`, `imap_host`, `imap_port` и `sent_folder`. Ошибка сохранения
копии не запускает повторную SMTP-отправку и поэтому не создаёт дубль.

После подтверждения отправки сервер помечает исходное входящее письмо флагами
`Seen`, `Answered` и `Flagged`: письмо становится прочитанным, получает признак
ответа и заметную звёздочку в почтовом интерфейсе.

**Пароль Яндекса** — это *пароль приложения* (Яндекс ID → Безопасность →
Пароли приложений → «Почта»), а не пароль от аккаунта.

## Запуск

```bash
# Проверить связь и увидеть очередь, ничего не отправляя:
python relay.py --config config.json --dry-run

# Один проход (удобно для cron):
python relay.py --config config.json --once

# Постоянный цикл (демон):
python relay.py --config config.json
```

### Автозапуск

- **cron** (раз в минуту): `* * * * * cd /path/to/email_relay && ./.venv/bin/python relay.py --config config.json --once >> relay.log 2>&1`
- **systemd / launchd / автозагрузка Windows** — запускать `relay.py --config config.json` как службу.

## Несколько компьютеров

Скрипт **безопасно** запускается на 2–3 машинах одновременно. В рабочем цикле он
использует `POST /email-outbox/claim`, который атомарно «захватывает» письма за
воркером (`SKIP LOCKED`), поэтому два релея не отправят одно письмо дважды.

- У каждой машины свой `worker_id` (по умолчанию `хост:pid`; можно задать в
  `config.json` полем `worker_id`).
- Если машина «зависнет», не отметив письмо, через `claim_lease_seconds`
  (по умолчанию 300 с) захват истекает и письмо заберёт другой воркер.
- `--dry-run` использует `/pending` (только смотрит, ничего не захватывает).
- Если сервер старый и `/email-outbox/claim` ещё не задеплоен (404), релей сам
  откатывается на `/pending` и пишет предупреждение — тогда одновременный запуск
  нескольких машин снова рискует дублями (держи один активный до деплоя).

Каждой машине по-прежнему нужны SMTP-данные того from-адреса, с которого она
отправляет (в `smtp_accounts`).

## Ошибки и повторы

- Ошибка отправки → `mark-error` с `retry=true`: письмо снова станет `pending`,
  релей попробует позже. После 5 неудачных попыток письмо переходит в `error`
  (видно в карточке рекламации → «Переписка»).
- Нет SMTP-настроек для `from` → `mark-error` без ретрая (нужно поправить
  `config.json`).
