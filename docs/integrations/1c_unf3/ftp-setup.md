# FTP-канал для синхронизации с 1С:УНФ

1С не может обращаться к нашему серверу «внутрь», а мы не можем достучаться до
её приватного адреса `172.22.0.90`. Решение: **1С сама ходит наружу** на наш
FTP-сервер, кладёт туда свои сообщения обмена и забирает наши.

Транспорт выбран потому, что начальная выгрузка EnterpriseData (справочники,
контрагенты, номенклатура) весит десятки мегабайт — почта такое не потянет.

---

## Важно про безопасность — прочитать до начала

**Обычный FTP передаёт логин и пароль в открытом виде.** Защищённое соединение
(FTPS) в этой версии транспорта 1С не поддерживается — в диалоге настройки есть
только «Пассивное соединение», галки шифрования нет.

Поэтому обязательны три меры:

1. **Нестандартный порт** (2121 вместо 21) — резко снижает поток
   автоматических переборов от ботов.
2. **Длинный случайный пароль**, используемый только здесь.
3. **Ограничение по IP** — сразу после первого успешного подключения смотрим
   в логах адрес сервера Рарус и закрываем доступ всем остальным.

Пункт 3 — ключевой. До него канал открыт всему интернету, поэтому не тяните:
настройте 1С в тот же день, когда поднимете FTP.

## Что уже сделано в репозитории

Править compose на сервере руками не нужно — всё лежит в git и приедет
деплоем:

- в `infra/dev/docker-compose.prod.yaml` добавлен сервис `ftp` и том
  `onec_exchange`;
- этот же том подключён к `web` и `scheduler` как `/app/onec_exchange`;
- в `.github/workflows/main.yml` деплой поднимает `ftp` — но **только если**
  задан пароль (иначе пропускает, чтобы не выставить наружу FTP без пароля).

Вам остаётся создать файл с паролем на сервере и открыть порты.

---

## Шаг 1. Создать `infra/dev/.env` на сервере

Это **отдельный файл**, не корневой `.env`. Так работает подстановка `${...}`
в compose: она читает `.env` из каталога compose-файла. Плюс FTP-контейнер
смотрит наружу, и давать ему все секреты проекта было бы неосмотрительно.

```bash
cd /root/DZ_fastapi/infra/dev
cat > .env <<'EOF'
FTP_USER=onec
FTP_PASSWORD=ВСТАВЬТЕ_СГЕНЕРИРОВАННЫЙ_ПАРОЛЬ
FTP_PUBLIC_HOST=dragonzap.online
FTP_PORT=2121
EOF
chmod 600 .env
```

Пароль сгенерировать:

```bash
openssl rand -base64 24
```

Файл в `.gitignore`, деплой его не перезапишет.

> Если вы раньше добавляли `ONE_C_FTP_USER` / `ONE_C_FTP_PASSWORD` в корневой
> `.env` — их можно удалить, они не используются. В корневом `.env` от этой
> задачи нужен только `ONE_C_EXCHANGE_DIR=/app/onec_exchange`.

## Шаг 2. Порты — проверить, а не открывать

На этом сервере `ufw` **выключен** (`ufw status` → `Status: inactive`), поэтому
входящие порты ничем не фильтруются и открывать ничего не нужно. Команды
`ufw allow` в неактивном состоянии просто записывают правила «на будущее» и ни
на что не влияют.

> ⚠️ **Не включайте `ufw enable` без подготовки.** Политика по умолчанию
> заблокирует входящие соединения, включая SSH, и доступ к серверу пропадёт.
> Если когда-нибудь понадобится включить — сначала `sudo ufw allow OpenSSH`,
> и только потом `enable`.

Убедитесь только, что порты никем не заняты:

```bash
sudo ss -tulpn | grep -E ':(21|2121|30000)\b'
sudo docker ps -a --format '{{.Names}}\t{{.Ports}}' | grep -i ftp
```

Если что-то уже слушает 2121 или диапазон 30000–30009, наш контейнер не
стартует с ошибкой «port is already allocated».

## Шаг 3. Задеплоить

Обычный пуш в `main` — деплой сам поднимет `ftp` и пересоздаст `web`
и `scheduler` с общим томом. Проверить:

```bash
sudo docker ps | grep dz_ftp
sudo docker logs dz_ftp --tail 30
```

## Шаг 4. Проверить снаружи

С вашего Mac:

```bash
curl -v --ftp-pasv "ftp://onec:ПАРОЛЬ@dragonzap.online:2121/"
```

Ожидаем `230 Login successful` и пустой список файлов.

## Приложение: старый вариант — править compose вручную

На сервере в `/root/DZ_fastapi/docker-compose.yaml` (или в
`docker-compose.prod.yaml` — где у вас описаны сервисы) добавьте:

```yaml
  ftp:
    image: delfer/alpine-ftp-server:latest
    container_name: dz_ftp
    restart: always
    env_file: .env
    environment:
      # логин|пароль|домашний каталог|uid — пароль подставляется из .env
      USERS: "${ONE_C_FTP_USER}|${ONE_C_FTP_PASSWORD}|/ftp/${ONE_C_FTP_USER}|1000"
      # публичный адрес — нужен для пассивного режима
      ADDRESS: dragonzap.online
      MIN_PORT: 30000
      MAX_PORT: 30009
    ports:
      - "2121:21"
      - "30000-30009:30000-30009"
    volumes:
      - onec_exchange:/ftp/${ONE_C_FTP_USER}
```

И в конец файла, в секцию `volumes:`:

```yaml
volumes:
  onec_exchange:
```

## Шаг 1.5. Переменные в `.env` на сервере

В `/root/DZ_fastapi/.env` добавьте:

```
ONE_C_FTP_USER=onec
ONE_C_FTP_PASSWORD=<сгенерированный пароль>
ONE_C_EXCHANGE_DIR=/app/onec_exchange
```

Пароль сгенерируйте так:

```bash
openssl rand -base64 24
```

Кто что читает — чтобы не путаться:

| Переменная | Кто использует |
|---|---|
| `ONE_C_FTP_USER`, `ONE_C_FTP_PASSWORD` | **только** docker compose (сервис `ftp`) и сама 1С |
| `ONE_C_EXCHANGE_DIR` | приложение — здесь оно ищет файлы обмена |
| `ONE_C_EXCHANGE_LOGIN/PASSWORD` | другое! Это доступ 1С к нашему API «Обмен с сайтом» |

Приложению пароль от FTP **не нужен**: файлы оно читает напрямую с общего
тома, а не по протоколу FTP.

## Шаг 2. Дать приложению доступ к той же папке

Чтобы наш сервис мог читать сообщения от 1С и класть свои, тот же том нужно
подключить к `web` и `scheduler`. В их описании в `volumes:` добавьте строку:

```yaml
      - onec_exchange:/app/onec_exchange
```

## Шаг 3. Открыть порты

```bash
sudo ufw allow 2121/tcp
sudo ufw allow 30000:30009/tcp
sudo ufw status
```

Если вместо `ufw` используется другой межсетевой экран или порты фильтруются у
хостера — открыть те же: **2121** и диапазон **30000–30009**.

## Шаг 4. Поднять и проверить

```bash
cd /root/DZ_fastapi
sudo docker compose -f docker-compose.yaml -f docker-compose.prod.yaml up -d ftp
sudo docker logs dz_ftp --tail 50
```

Проверка снаружи (с вашего Mac):

```bash
curl -v --ftp-pasv "ftp://onec:ПАРОЛЬ@dragonzap.online:2121/"
```

Ожидаем `230 Login successful` и пустой список файлов.

## Шаг 5. Настройки в 1С

В диалоге «FTP-сервер» мастера синхронизации:

| Поле | Значение |
|---|---|
| Сервер и каталог | `dragonzap.online` |
| Порт | `2121` |
| **Пассивное соединение** | **включить обязательно** |
| Имя пользователя | `onec` |
| Пароль | тот, что задали в `USERS` |
| Максимальный размер файла-сообщения | оставить «Без ограничения» |
| Архивировать файл исходящего сообщения | **включить** — сжатие ускорит обмен |
| Пароль архива | оставить пустым |
| Транслитерация имени | не включать |

Пассивный режим обязателен: наш FTP работает за NAT контейнера, в активном
режиме соединение не установится.

Затем нажмите **«Проверить подключение»**. Должно ответить успехом.

## Шаг 6. Закрыть доступ по IP — сразу после первого подключения

Посмотрите, с какого адреса пришла 1С:

```bash
sudo docker logs dz_ftp | grep -iE "connect|login" | tail -20
```

Найдя адрес, ограничьте доступ только им. **Через `ufw` это не сработает:**
Docker публикует порты, напрямую правя iptables, и проходит мимо правил ufw.
Фильтровать нужно в цепочке `DOCKER-USER`, которую Docker специально оставляет
для пользовательских правил:

```bash
# разрешить только адрес 1С
sudo iptables -I DOCKER-USER -p tcp -s АДРЕС_1С --dport 21 -j RETURN
sudo iptables -I DOCKER-USER -p tcp -s АДРЕС_1С --dport 30000:30009 -j RETURN
# остальным — запретить
sudo iptables -A DOCKER-USER -p tcp --dport 21 -j DROP
sudo iptables -A DOCKER-USER -p tcp --dport 30000:30009 -j DROP
```

Порт указывается **внутренний** (21), а не внешний (2121): правила в
`DOCKER-USER` применяются после трансляции адресов.

Правила iptables не переживают перезагрузку. Чтобы сохранить:

```bash
sudo apt install iptables-persistent
sudo netfilter-persistent save
```

Проверить, что вышло:

```bash
sudo iptables -L DOCKER-USER -n -v --line-numbers
```

После этого проверьте из 1С «Проверить подключение» ещё раз — должно
по-прежнему работать, а снаружи с другого адреса подключиться уже не выйдет.

## Что дальше

Когда канал заработает, в 1С нужно пройти оставшиеся этапы мастера и выполнить
**начальную выгрузку данных**. 1С положит на FTP свой первый файл сообщения.

**Этот файл — главная цель первого этапа.** По нему реализуется наша сторона
формата EnterpriseData: разбор входящих сообщений и формирование ответных.

Забрать его можно так:

```bash
sudo docker exec dz_ftp ls -la /ftp/onec
```
