# Обмен с 1С:УНФ 3 через «Синхронизацию данных» (EnterpriseData)

Цель — уйти от «Обмена с сайтом» (он умеет только заказы и порождает двойной
ввод) к штатной синхронизации через универсальный формат EnterpriseData.
Доработок конфигурации 1С не требуется: в УНФ этот механизм уже есть — именно
через него УНФ штатно синхронизируется с 1С:Бухгалтерией.

Этот документ — **разведка перед разработкой**. Его задача: выяснить, что
именно поддерживает ваша УНФ, и получить от неё реальный файл обмена. По этому
файлу дальше пишется наша сторона.

---

## Целевая схема (к чему идём)

| Что | Где хозяин | Как попадает во вторую систему |
|---|---|---|
| Заказы, закупки, склад, производство | **Наша система** | движения уезжают в 1С готовыми документами |
| Номер реализации, УПД, ЭДО с клиентом | **1С** | номер возвращается к нам в `external_id` |
| Себестоимость, НДС, отчётность | **1С** | считает сама по полученным движениям |
| Остатки | мастер — наша система | сходятся сами, т.к. 1С видит все движения |

Ключевое условие: в 1С должны уезжать **все** виды движений. Если хоть один
не передаётся (сегодня, например, поступления), остатки разойдутся.

---

## Параметры обмена (из файла настроек, созданного 1С)

Мастер синхронизации в УНФ выгружает файл настроек — из него взяты значения
ниже. **Пароль FTP лежит в том файле открытым текстом**, поэтому сам файл
хранить и пересылать нельзя; здесь только безопасная часть.

| Параметр | Значение |
|---|---|
| План обмена | `СинхронизацияДанныхЧерезУниверсальныйФормат` |
| Формат | `http://v8.1c.ru/edi/edi_stnd/EnterpriseData` |
| Узел 1С (отправитель) | **`НФ`** |
| Наш узел (получатель) | **`ДЗ`** |
| Префикс 1С | `НФ` |
| Наш префикс | `ДЗ` |
| Транспорт | FTP, пассивный режим, порт 2121, путь `ftp://dragonzap.online/` |
| Сжатие исходящих | включено — 1С кладёт **zip**, не голый XML |
| Ограничение размера сообщения | нет |

**Поддерживаемые версии формата EnterpriseData** (по данным самой 1С):
`1.6, 1.7, 1.8, 1.10, 1.14, 1.15, 1.16, 1.17, 1.18, 1.19, 1.20, 1.22`.

Какую версию использовать в ответных сообщениях — определим по заголовку
первого сообщения, которое пришлёт 1С, а не выберем наугад.

Счётчики на старте: `SentNo = 0`, `ReceivedNo = 0` — обмен ещё ни разу не
выполнялся.

## Что реально можно обменивать (из рукопожатия 1С)

Первое сообщение `Message_НФ_ДЗ.zip` — это рукопожатие: данных нет, зато есть
полный список типов объектов. Всего **134 типа**, из них **87 в обе стороны**.

Ключевое для нас (всё доступно **в обоих направлениях**):

| Задача | Объект EnterpriseData |
|---|---|
| Отгрузки клиентам | `Документ.РеализацияТоваровУслуг` |
| Поступления от поставщиков | `Документ.ПоступлениеТоваровУслуг` |
| Производство / сборка | `Документ.СборкаТоваров`, `Документ.ПередачаМатериаловВПроизводство` |
| Оприходование | `Документ.ОприходованиеТоваров` |
| Списание | `Документ.СписаниеЗапасов`, `Документ.СписаниеНедостач` |
| Перемещение | `Документ.ПеремещениеТоваров` |
| Инвентаризация | `Документ.ИнвентаризацияТоваров` |
| Заказы клиентов и поставщикам | `Документ.ЗаказКлиента`, `Документ.ЗаказПоставщику` |
| Цены | `Документ.УстановкаЦенНоменклатуры` |
| Контрагенты | `Справочник.Контрагенты` |
| Номенклатура | `Справочник.Номенклатура`, `ХарактеристикиНоменклатуры`, `ШтрихкодыНоменклатуры` |
| Склады, организации | `Справочник.Склады`, `Справочник.Организации` |
| Спецификации (для производства) | `Справочник.СпецификацииНоменклатуры` |

Важно: документ отгрузки называется **`РеализацияТоваровУслуг`** (как в УТ), а не
«Расходная накладная» — в формате EnterpriseData имена унифицированы.

Это полностью закрывает исходный список требований: отгрузки, поступления,
складские документы, производство, заказы, контрагенты и номенклатура —
причём двусторонне.

### Структура рукопожатия

```xml
<Message xmlns:msg="http://www.1c.ru/SSL/Exchange/Message">
  <msg:Header>
    <msg:Format>http://v8.1c.ru/edi/edi_stnd/EnterpriseData</msg:Format>
    <msg:CreationDate>...</msg:CreationDate>
    <msg:Confirmation>
      <msg:ExchangePlan>СинхронизацияДанныхЧерезУниверсальныйФормат</msg:ExchangePlan>
      <msg:To>ДЗ</msg:To><msg:From>НФ</msg:From>
      <msg:MessageNo>0</msg:MessageNo><msg:ReceivedNo>0</msg:ReceivedNo>
    </msg:Confirmation>
    <msg:AvailableVersion>1.22</msg:AvailableVersion>  <!-- и другие -->
    <msg:NewFrom>GUID-узла</msg:NewFrom>
    <msg:AvailableObjectTypes>...</msg:AvailableObjectTypes>
  </msg:Header>
</Message>
```

Имя файла: `Message_<Отправитель>_<Получатель>.zip` → от 1С к нам
`Message_НФ_ДЗ.zip`, наш ответ должен называться `Message_ДЗ_НФ.zip`.

## Результаты разведки (сентябрь 2026)

База: `1R104480_UNF30_qwfnkms98e`, УНФ **3.0.14.123** (не базовая), аренда
у 1С-Рарус. Веб-сервер IIS/10.0, адрес `172.22.0.90` — **приватный**, доступен
только через VPN (L2TP, клиентский профиль на Mac, интерфейс `ppp0`).

### Что опубликовано у базы

| Адрес | Ответ | Вывод |
|---|---|---|
| `/` | 200 | веб-клиент работает |
| `/odata/standard.odata/` | 404 | **OData НЕ опубликован** |
| `/ws/` | 404 | SOAP-сервисы не опубликованы |
| `/hs/<имя>` | 404 при верной авторизации | **HTTP-сервисы опубликованы и работают** |

`404` на `/hs/` при успешной авторизации — это «нет сервиса с таким именем»,
а не «нет маршрута». Значит через HTTP-сервисы путь открыт.

### Две разные настройки OData — их легко перепутать

1. **«Настройки стандартного интерфейса OData»** внутри 1С — задаёт *состав*
   объектов. Доступна администратору базы.
2. **Публикация OData на веб-сервере** (`default.vrd`, `enableStandardOData`) —
   определяет, *существует ли endpoint*. Файл на сервере Рарус, самим не
   изменить.

Первая без второй бесполезна. Сейчас выключена именно вторая.

### Две пары учётных данных — тоже легко перепутать

- `ONE_C_EXCHANGE_LOGIN/PASSWORD` — 1С подключается **к нам** (канал
  «Обмен с сайтом»).
- Пользователь 1С (например `dz_integration`) — мы подключаемся **к 1С**.
  Логин обязательно **латиницей**: кириллица ломает Basic-авторизацию.
  Должна быть включена «Аутентификация 1С:Предприятия».

### Ключевое ограничение сети

`172.22.0.90` недоступен из интернета. Значит наш сервер не может обращаться
к 1С напрямую. Отсюда приоритет схем, где **1С ходит наружу сама**
(синхронизация через FTP или почту) либо где работает агент внутри VPN.

## Шаг 0. Проверить, что синхронизация вообще доступна

**Это самый важный шаг — если тут «нет», дальше идти некуда.**

1. В 1С: меню **«О программе»** (обычно значок «i» или Главное → О программе).
2. Записать точное название и версию конфигурации, например:
   `1С:Управление нашей фирмой, редакция 3.0 (3.0.x.x)`.
3. Убедиться, что это **НЕ «Базовая версия»**.

> ⚠️ В **базовых** версиях 1С обмен данными и синхронизация **не поддерживаются**
> вообще. Если у вас базовая — синхронизацию сделать нельзя, потребуется
> переход на ПРОФ. Это ограничение лицензии, а не настройки.

## Шаг 0.5. Две частые ошибки на старте

### Не перепутайте инструмент

В 1С есть похожая по названию, но **совершенно другая** обработка —
**«Универсальный обмен данными в формате XML»**. Это механизм **Конвертации
данных 2.0**: он работает только с готовым файлом *правил обмена*, которые
создаются в отдельной программе «Конвертация данных 2.0».

**Нам нужна не она.** Нам нужен раздел **«Синхронизация данных»** — он
использует формат EnterpriseData и правил обмена не требует.

### Работайте в приложении, а не в браузере

Если открыть 1С в браузере, при обращении к файлам появится ошибка:

> `File system extension is not supported by this web browser`
> «Не удалось установить или подключить расширение работы с файлами»

Веб-клиент не может обращаться к диску без специального расширения 1С.
Решения:

1. **Рекомендуется:** открыть базу в приложении **«1С:Предприятие»** (тонкий
   клиент) — файловые операции работают сразу.
2. Либо установить «Расширение работы с файлами» 1С в браузере.

### Уточните, где живёт база

От этого зависит выбор транспорта на Шаге 4:

- **База локальная** (на вашем сервере или компьютере) — годится самый простой
  вариант: обмен через каталог на диске.
- **База в облаке** (аренда, 1С:Фреш) — 1С не видит ваш диск, каталог отпадает.
  Останутся FTP или веб-сервис.

## Шаг 1. Включить синхронизацию данных

1. Откройте **Настройки** (или «Компания» / «Администрирование» — зависит от
   релиза). Проще всего найти через **поиск по разделам**: нажмите поиск и
   введите `Синхронизация данных`.
2. Найдите раздел **«Синхронизация данных»**.
3. Включите флажок **«Синхронизация данных»**.
4. Задайте **префикс информационной базы** (2 символа, например `УН`). Он нужен,
   чтобы номера документов из разных баз не сталкивались. Запишите его.

---

## Шаг 2. Создать настройку синхронизации

1. В том же разделе — **«Настройки синхронизации данных»** → создать новую.
2. В списке программ ищите вариант вида **«Обмен с программой, поддерживающей
   формат EnterpriseData»** / **«Синхронизация через универсальный формат»**.
   Точная формулировка меняется от релиза — суть в словах *универсальный
   формат* или *EnterpriseData*.
3. **Не завершайте мастер до конца.** Нам сначала нужно снять информацию.

---

## Шаг 3. Зафиксировать версию формата — критично

В мастере (или в настройке после создания) должна быть указана **версия формата
EnterpriseData**: например `1.7`, `1.9`, `2.0`.

**Запишите её.** От версии зависит XML-схема, которую я буду реализовывать.
Если предлагается выбор из нескольких — запишите весь список.

---

## Шаг 4. Выбрать способ обмена (транспорт)

Мастер предложит варианты. Что нам подходит, по убыванию удобства:

1. **Каталог на диске** — 1С кладёт XML в папку, забирает оттуда же ответ.
   Самый простой и надёжный для старта. Папку можно синхронизировать с сервером
   (сетевой диск, rclone, скрипт).
2. **FTP-ресурс** — то же самое, но через FTP. Удобно, если 1С и сервер в разных
   сетях.
3. **Прямое подключение через интернет (веб-сервис)** — 1С ходит к нам по HTTP.
   Красиво, но требует, чтобы мы реализовали SOAP/HTTP-сервис по контракту 1С.
   Дольше в разработке.

**Рекомендация на старт: каталог на диске или FTP.** Начать можно даже с
локальной папки — просто чтобы получить образцы файлов.

Запишите, какие варианты предлагаются в вашей УНФ.

---

## Шаг 5. Настроить состав данных

В настройке синхронизации будет раздел вида «Правила отправки данных» /
«Состав отправляемых данных». Посмотрите и запишите:

- какие **организации** можно выбрать (нам нужна та, по которой ведётся учёт);
- с какой **даты** начинать выгрузку;
- какие **объекты** вообще перечислены в списке (документы и справочники).

Особенно интересует, есть ли в списке:
- расходные накладные (реализация),
- приходные накладные (поступление),
- производство / сборка,
- складские операции (оприходование, списание, инвентаризация),
- контрагенты и номенклатура.

---

## Шаг 6. Получить реальный файл обмена — главный результат разведки

1. Завершите мастер, выбрав **каталог на диске** и указав пустую папку.
2. Запустите синхронизацию вручную (кнопка **«Синхронизировать»**).
3. 1С сообщит, что вторая сторона не ответила — **это нормально и ожидаемо**,
   нас интересует не результат, а файл.
4. Загляните в указанную папку: там должен появиться XML-файл выгрузки
   (обычно `Message_<...>.xml` или в подпапке).

**Пришлите мне этот файл.** По нему я увижу точную схему, версию формата,
состав данных и смогу написать нашу сторону не по документации, а по факту.

Если в папке пусто — значит 1С нечего выгружать. Заведите в 1С один тестовый
документ (например, расходную накладную) и повторите синхронизацию.

---

## Что прислать по итогам разведки

1. Точное название и версия конфигурации (Шаг 0), не базовая ли.
2. Версия (или список версий) формата EnterpriseData (Шаг 3).
3. Список доступных транспортов (Шаг 4).
4. Список объектов из состава данных (Шаг 5) — можно скриншотом.
5. **XML-файл выгрузки** (Шаг 6) — самое ценное.

---

## Чего делать НЕ надо

- Не снимайте конфигурацию с поддержки и не меняйте типовую — для этой схемы
  доработки не нужны, а снятие с поддержки сломает обновления.
- Не настраивайте синхронизацию сразу на «боевой» период за всю историю —
  начните с текущей даты и одного-двух документов.
- Не отключайте текущий «Обмен с сайтом» — он не мешает и продолжит возить
  заказы, пока новый канал не заработает.

---

## План разработки после разведки

1. **Отгрузки → расходные накладные.** Убирает ручное «создать на основании».
2. **Поступления → приходные накладные.** Закрывает главную дыру в остатках.
3. **Производство** — списание материалов и выпуск продукции (себестоимость).
4. **Справочники** — контрагенты и номенклатура, без дублей.
5. **Возврат номера и идентификатора из 1С** в поля `external_id` и номер
   документа учёта.
