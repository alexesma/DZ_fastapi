# Ручная сборка и скачивание прайса клиента

Кнопки в карточке клиента открывают окно готового файла и фоновой задачи.

- «Скачать готовый» отдаёт сохранённый файл без пересборки. Дата сборки показана явно: файл не обещает учитывать более поздние изменения источников или настроек.
- «Обновить прайс» создаёт задачу `build`.
- «Отправить этот файл» создаёт задачу `send` с выбранной версией файла. Цены и строки не пересчитываются, получатели и почтовые аккаунты берутся из текущей конфигурации.
- «Сформировать новый и отправить» сначала пересобирает прайс, затем отправляет его.

HTTP POST `/customers/{customer_id}/pricelist-configs/{config_id}/jobs` возвращает 202 и номер задачи. GET того же URL возвращает последнюю задачу, этап, процент и последний готовый файл. Оба метода доступны администратору и проверяют принадлежность конфигурации клиенту. Скачивание использует существующий маршрут `drafts/{pricelist_id}/download`.

Задачи сохраняются в `customerpricelistjob`. Планировщик проверяет очередь каждые 10 секунд и обрабатывает одну ручную задачу за раз. PostgreSQL advisory lock исключает параллельных обработчиков. Частичный уникальный индекс исключает две активные задачи одной конфигурации. Общая блокировка конфигурации также защищает от пересечения со старым HTTP API и рассылкой по расписанию.

Прогресс сохраняется отдельными короткими транзакциями. Проценты обозначают этапы, а не точный прогноз времени. Закрытие окна не отменяет обработку; повторное открытие читает её состояние из БД.

Если обработчик остановился, следующий обработчик помечает незавершённую задачу как прерванную. Отправка автоматически не повторяется: часть писем могла уже уйти. Перед повтором нужно проверить relay и почтовый сервис. Статус `queued` у результата отправки означает очередь relay, а не доставку получателю.

## Развёртывание

1. Применить миграцию `c5e7f9a1b3d2` (`alembic upgrade head`).
2. Обновить API и контейнер `dz_scheduler` одной версией backend.
3. Обновить frontend.
4. На тестовой конфигурации запустить **сборку без отправки**. Проверить этапы, закрытие/повторное открытие окна и скачивание готового файла.

Если задача остаётся в `queued`, проверить работу `dz_scheduler` и регистрацию задания `manual_customer_pricelists`. Старые синхронные маршруты сохранены для совместимости; новое окно ими не пользуется.
